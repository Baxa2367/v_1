# Демо для защиты (5–7 минут)

## Подготовка (до комиссии)

```bash
# 1. база и контент
./build/lumina_migrator.exe
./build/lumina_seeder.exe            # первый раз; повторно: --reset

# 2. API
./build/lumina_server.exe            # :8080

# 3. клиент (dev)
cd frontend && npm run dev           # :5173
```

Откройте `http://localhost:5173`, язык — қазақша/русский, войдите как
`alisher@lumina.kz` / `Lumina2026!`.

## Сценарий (по шагам)

**0:00–0:30 · Лендинг и вход.**
Покажите трилингвальный переключатель KZ/RU/EN и вход. Расскажите: «вся игровая
логика на сервере, клиент только отображает».

**0:30–1:30 · Дашборд.**
XP-бар и уровень, серия 12+ дней, дневная цель, 4 метрики, герой-блок
«Продолжить», AI-совет, квесты, мини-рейтинг, график активности.

**1:30–2:30 · Карта курса.**
Курс «Основы C++»: 8 уровней, боссы 4 и 8, звёзды, закрытые уровни,
mastery-карта справа. Нажмите текущий уровень.

**2:30–3:30 · Задание.**
Покажите таймер, подсказку (XP-штраф), выберите ответ, нажмите «Проверить».
Обратите внимание: `answer_key` не приходил до отправки (Network tab),
результат пришёл с сервера вместе с XP, объяснением и достижением.

**3:30–4:30 · AI-решение.**
После ответа нажмите «AI тапсырмасы» — появится задание с объяснением, почему
оно выбрано (например: «серия ошибок по теме "Циклы" — сложность снижена»).
Откройте `/ai`: прогноз до следующего уровня, риск отсева, mastery по темам,
персональные советы.

**4:30–5:15 · Рейтинг и достижения.**
`/leaderboard`: global/weekly/course/season, своя позиция, ▲▼.
`/achievements`: 45 достижений, 4 редкости, прогресс.

**5:15–6:00 · Статистика и отчёты.**
`/stats`: XP-график, radar тем, heatmap, прогресс курсов, слабые темы.
Скачайте CSV/XLSX/PDF — файл формируется на C++.

**6:00–6:40 · Преподаватель и админ.**
Войдите как `aigerim@lumina.kz` → `/teacher`: аналитика группы, зона риска,
слабые темы. Затем `admin@lumina.kz` → `/admin`: метрики, роли, античит-флаги,
сезоны.

**6:40–7:00 · Итог.**
`node scripts/demo.mjs` — автоматический e2e-сценарий (регистрация → задание →
XP → достижение → AI → рейтинг → отчёты), все проверки зелёные.

## Что сказать про архитектуру (30 секунд)

«C++20 + Drogon, PostgreSQL, libpqxx. XP, достижения, серии и рейтинги
считаются в одной транзакции с блокировкой строки студента. Попытка
идемпотентна по `attempt_token`. AI — отдельная библиотека: BKT-модель mastery
+ политика ZPD, каждое решение объяснимо и логируется. 320 заданий, 45
достижений, 30 квестов, 60 советов — всё в сидах, kk+ru.»

## Вероятные вопросы комиссии

**Почему C++ на бэкенде?** Требование ТЗ; Drogon даёт асинхронный HTTP/WS,
фильтры и таймеры, а libpqxx — полный контроль SQL и транзакций.

**Как гарантируется, что клиент не накрутит XP?** Клиент присылает только
ответ и токен попытки. Проверка, формула, начисления и достижения — в C++,
в транзакции; `answer_key` не покидает сервер до сабмита; повторный запрос
с тем же токеном возвращает сохранённый результат.

**Где хранятся правильные ответы?** В `tasks.answer_key` (JSONB), которое не
сериализуется в API. Санитайзер задач вырезает ключ и скрытые тесты.

**Как работает AI?** Для пары (студент, тема) хранится BKT-состояние. После
попытки — байесовское обновление с slip/guess и забыванием (half-life 21 день).
Политика: 70 % ZPD (60–80 % успеха), 20 % слабая тема, 10 % вызов; 3 ошибки
подряд → сложность −1 и совет. Решение пишется в `ai_decisions` с признаками.

**Что если Redis недоступен?** Рейтинги считаются SQL-запросами и
снапшотами; Redis — опциональный ускоритель. Система работает без него.

**Как обеспечена идемпотентность?** Уникальный `attempt_token`, сохранённый
ответ в `attempts.response`, проверка внутри транзакции.

**Почему 320 заданий — не сгенерированы ли они мусором?** Контент собран по
учебным программам, у каждого задания объяснение и 2–3 подсказки; валидатор
проверяет структуру, типы, ключи ответов и покрытие типов.

**Ограничения?** Песочница кода на Windows не изолирует сеть (Job Objects:
CPU/RAM/время); для production — контейнер + nsjail. Redis опционален.
LLM включается ключом, без него — банк заданий и шаблоны.

**Что дальше?** Вынести песочницу в отдельный сервис, добавить Redis
sorted sets, PWA/мобильное приложение, A/B-тесты политики AI.
