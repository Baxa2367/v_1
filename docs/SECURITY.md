# Безопасность

## Аутентификация и сессии

* Пароли — **Argon2id** (`libsodium crypto_pwhash_str`, interactive limits).
* Access JWT — HS256, TTL 120 минут, содержит `sub`, `role`, `locale`, `typ`,
  `iat`, `exp`, `jti`; подпись проверяется constant-time сравнением.
* Refresh — 256-битный случайный токен, в БД хранится только SHA-256 хэш,
  TTL 30 дней, **ротация** при каждом refresh; повторное использование
  отозванного токена отклоняется.
* Logout/блокировка пользователя отзывают все refresh-токены.
* RBAC: `student`, `teacher`, `admin`; фильтры `AuthFilter`, `TeacherFilter`,
  `AdminFilter` на каждом маршруте (кроме публичных auth/health/meta/docs).

## Авторизация и данные

* Все SQL-запросы — параметризованные (`pqxx::exec_params`); пользовательский
  ввод никогда не конкатенируется в SQL.
* Проверка владения: преподаватель редактирует только свои курсы
  (`assertTeacherOfCourse`), студент видит только свои попытки/награды.
* `answer_key` и скрытые тесты не сериализуются в API; `Grading::sanitizeTask`
  вырезает их и перемешивает варианты.
* Экспорт отчётов ограничен данными текущего пользователя.
* Загрузок файлов нет (кроме кода в песочницу, ≤ 20 КБ).

## Игровая целостность

* XP, рейтинги, достижения, серии и звёзды считаются в C++ внутри транзакции
  с `SELECT ... FOR UPDATE` по строке `students`.
* `attempt_token` уникален; повторная отправка возвращает сохранённый ответ,
  XP не начисляется дважды.
* Лимиты: 6 попыток на задание в день, cooldown 15 секунд, серверное время.
* Античит: ответ быстрее 1.2 с (кроме timed quiz), превышение лимита времени,
  массовые одинаковые ответы разных студентов за 15 минут → `suspicious`,
  XP = 0 и запись в `anticheat_flags`; преподаватель/админ видит флаги.
* Аудит действий staff — `audit_log`.

## Транспорт и HTTP

* Rate limiting: token bucket по IP (по умолчанию 600 req/min, настраивается).
* CORS-заголовки, `X-Content-Type-Options: nosniff`, `X-Frame-Options`,
  `Referrer-Policy`; preflight `OPTIONS` обрабатывается до маршрутизации.
* Единый формат ошибок без stack trace и SQL-деталей.
* Статика отдаётся C++ сервером; API и UI — один origin.

## Песочница кода

* Компиляция `g++ -std=c++20 -O2` в отдельном временном каталоге; запуск —
  отдельный процесс с таймаутом на тест (3 с) и лимитом памяти 256 МБ
  (Windows Job Objects / POSIX `setrlimit(RLIMIT_AS, RLIMIT_CPU)`).
* Компиляция ограничена 30 секундами; исходник ≤ 20 КБ; максимум 8 тестов.
* stdout/stderr ограничены 4 КБ в ответе.

**Ограничение Windows-раннера:** нет network/filesystem namespace. Для
production используйте контейнер и `nsjail`/`isolate`:

```yaml
# пример политики nsjail
mode: l
clone_newnet: true
clone_newuser: true
rlimit_cpu: 3
rlimit_as: 256
```

Интерфейс `sandbox/sandbox.h` позволяет заменить реализацию без изменения
сервисов.

## Секреты

`JWT_SECRET`, `DATABASE_URL`, `ANTHROPIC_API_KEY` читаются из переменных
окружения/.env; в репозитории только `.env.example`. Для production задайте
длинный случайный `JWT_SECRET` и смените пароль БД.

## Что осталось за рамками демо

* 2FA, OAuth-провайдеры.
* WAF и полноценный аудит сетевого периметра.
* Шифрование чувствительных полей на уровне БД (кроме хэшей паролей/токенов).
