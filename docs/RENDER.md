# Запуск Lumina на Render

Файл `render.yaml` описывает один веб-сервис с приложением и отдельную облачную PostgreSQL. Render собирает интерфейс и C++ API из `docker/Dockerfile`, запускает миграции, добавляет учебные курсы и проверяет `/healthz`.

## Подготовить Render

1. Добавьте содержимое папки `v_1` в приватный репозиторий GitHub и отправьте файлы проекта. Корень репозитория должен содержать `render.yaml` и папку `docker`. `.env`, локальные сборки, логи, загруженные файлы и зависимости исключены из Git через `.gitignore`.
2. В Render выберите **New → Blueprint** и подключите этот репозиторий. Укажите путь `render.yaml`, если файл не находится в корне репозитория.
3. Проверьте список ресурсов: `lumina` (веб-сервис) и `lumina-db` (PostgreSQL). Это бесплатная тестовая конфигурация: веб-сервис засыпает после 15 минут простоя, а PostgreSQL удаляется через 30 дней после создания. Перед продолжительным использованием выберите подходящий платный план.
4. Когда Render попросит значения `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD`, введите почту администратора и новый пароль длиной не менее 12 символов прямо в панели Render. Не добавляйте пароль в GitHub или `.env`.
5. Нажмите **Deploy Blueprint**. Render создаст базу, затем применит миграции и начальные учебные данные. Готовый сайт будет доступен по адресу Render.

В облачном режиме `DEMO_MODE=0`: опубликованные демо-пароли отключены. Локальная демо-среда сохраняет существующие тестовые аккаунты при `DEMO_MODE=1`.

На бесплатном запуске отдельный фоновый процесс `lumina_worker` не создаётся. Поэтому фоновые операции сезонов, ежедневных снимков рейтинга и сброса серий нужно включить отдельно на платном тарифе, если они потребуются.

Для обновления сайта отправляйте новые изменения в подключённую ветку GitHub. Render пересоберёт приложение. Не удаляйте `lumina-db`, если в ней уже есть пользовательские данные.
